# Codex Sleep State Sugar

适用于 Shadowrocket 的 Codex Responses HTTP 请求诊断与 state 管理脚本。默认保留客户端已有的 `x-codex-turn-state`，仅在身份、模型和轮次可确认时补充同轮复用，并通过提示栏通知观察状态。

**292/312 是这里观察到的 state 字符串长度，不是本项目的 HTTP 成功码，也不是模型质量指标。** 默认接受 10 块结构；带 Base64 填充时通常为 292 字符，去除填充后可能为 290 字符。结构检查无法验证服务端签名或保证服务端接受。

## 安装与升级

在 Shadowrocket 中添加或更新模块：

```text
https://raw.githubusercontent.com/ewsun22/csss/main/codex-state-shadowrocket.srmodule
```

启用模块，在 MITM 中为 `chatgpt.com`、`api.openai.com` 安装并信任证书，并确保目标请求经过 Shadowrocket。要看到提示栏通知，请允许 Shadowrocket 发送系统通知并开启横幅。

从旧版升级时，**模块和脚本都需要更新**。新版本默认 `mode=turn`，不会再自动跨会话打探针。使用新缓存键 `codex-turn-state-shadowrocket-v2`，不导入旧缓存，以免旧的共享身份缓存继续被使用。旧键 `codex-turn-state-shadowrocket-v1` 可以手动删除。脚本远程缓存更新间隔为 86400 秒；需要立即生效时，手动刷新远程脚本。

## 两种模式

| 行为 | `mode=turn`（默认） | `mode=experimental`（显式实验） |
| --- | --- | --- |
| 客户端已带 state | 保留，不覆盖 | 保留，不覆盖 |
| 新轮次没有 state | 正常放行，观察正式响应 | 尝试复用候选票，必要时先发探针 |
| 同轮后续请求 | 只补充本轮已采集的有效 state | 本轮票锁定，不在中途切换 |
| 跨轮复用与探针 | 关闭 | 开启，仍按认证、来源及模型隔离 |
| 本轮票过期或客户端接管 | 本轮透传，不重新选票 | 本轮透传，不重新选票 |

官方 Codex 客户端源码要求同轮保持 state 不变，不跨轮发送。默认模式据此限制复用范围。实验模式不符合这一默认使用约定，只用于明确选择的本地实验，不能保证质量改善、路由一致或服务端接受。

要选择实验模式，将模块**请求和响应两行**的 `mode=turn` 都改为 `mode=experimental`。只改一处会导致上下文无法匹配。实验探针使用当前请求的认证头发送额外短请求，会增加请求次数，可能带来额度消耗及额外等待。

## 请求识别与隔离

仅匹配 `chatgpt.com/backend-api/codex/responses` 和 `api.openai.com/v1/responses`。

- 模型需由 `x-codex-model`、路由提示或可解析 JSON 请求正文明确识别；来源相互冲突则透传。默认目标为 `gpt-6-astra`。
- 必须有 Authorization、完整 thread/session 标识和 `x-codex-turn-metadata.turn_id`。认证与账号信息先做 SHA-256 摘要后用于本地缓存键，不保存原始凭据。
- 关联请求与响应还需稳定的 `$request.id` 或 `x-request-id`；没有可靠关联时不注入、不发探针。
- 来源、认证摘要、账号、模型、模式与缓存策略共同隔离候选票；本轮缓存再加入完整 thread/turn 标识的摘要。
- 请求正文只用于读取模型，不修改、不保存；压缩正文或二进制正文不猜测内容。无法读取正文且没有可靠模型头时透传。
- 响应钩子未提供原请求正文时，可从同一认证与请求 ID 绑定的记录恢复已确认的模型上下文。

模块为请求脚本启用 `requires-body=true`；响应脚本不缓冲正式生成正文。具体设备能否提供正文和稳定请求 ID，仍需实际验证。原生 WebSocket 帧不在此 HTTP 脚本的处理范围内。

## 实验模式续期与异常处理

本地 TTL 默认 60 分钟，从解析出的签发时间计算，提前 30 秒停止注入。这个 TTL 是项目策略，不是服务端有效性保证。

进入最后 10 分钟后，**下一次尚未见过的新轮次请求**可以触发续期。同轮请求继续使用原状态；没有新轮次请求就不会后台定时采集。探针成功后也至少冷却 5 分钟，避免收到仍接近过期的新票时密集采集。

探针需要同时满足 HTTP 200、严格 SSE 完成事件、响应 ID 一致以及 state 结构与有效期检查。只有签发时间更晚的票才能替换已有候选票；相同或更旧的票不会延长本地有效期。正式响应只采集 HTTP 200 响应头，不能据此宣称生成完整成功。

普通续期失败时，未被标记异常且仍有效的旧候选票可以用于新轮次。连续两次有 state 的成功响应出现结构异常或与注入值不一致时，将候选票标记为需重新采集，后续新轮次不再选用该候选票；已锁定的旧轮次仍保持原状态。响应不带 state 时不改变计数；与注入值匹配的有效响应清零计数。HTTP 错误独立处理，不当作 state 形状异常。

探针及正式响应共享认证/限流/服务端失败的冷却状态：

- 普通临时失败按 5、10、20、30 分钟附近退避，带少量抖动，上限默认 30 分钟。
- 429 同时读取 `Retry-After` 秒数或日期，不缩短已存在的冷却。
- 401/403 默认冷却一小时；认证凭据变化后使用独立状态。
- 冷却不会阻止用户正式请求，只限制额外探针；正式请求不会自动重放。

探针 ID、独立探针代次和票代次可阻止常见的迟到回调覆盖、旧票异常污染新票。持久化是非原子读改写，**仍不能保证真正同时执行的脚本严格互斥**。探针进行中时其他请求正常放行；已开始的轮次不会被稍后成功的探针重新选票。

## 提示栏通知

- **292 打票成功**：每次注入 10 块票时发送，正文显示实际长度和本地剩余有效期。表示本地写入请求头，不代表上游已生成成功。
- **已采集**：成功存储本轮票或实验候选票时发送。
- **收到 312，请注意**：探针或正式响应观察到 312 字符 state 时发送；不等于已证实降智。
- **已安排重新采集**：异常达到阈值并成功保存状态后发送。
- **认证或访问失败／请求限流／网络异常／探针未完成**：显示异常及适用的探针等待时间。
- **本次未注入／缓存写入失败**：说明透传原因。

每次注入都会尝试通知，不做通知去重。系统权限或专注模式可能影响显示。通知失败不会阻断请求；缓存写入失败时停止该次注入，正常透传。

## 参数

请求和响应两行使用相同参数。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `mode` | `turn` | 同轮模式；`experimental` 开启跨轮实验 |
| `model` | `gpt-6-astra` | 必须明确匹配的目标模型 |
| `blocks` | `10` | 本地接受的加密块数；不是质量指标 |
| `ttl` | `3600` | 本地有效期秒数 |
| `renew` | `600` | 实验候选票提前续期窗口 |
| `cooldown` | `300` | 探针最小重试间隔 |
| `max_backoff` | `1800` | 普通失败退避上限，不能小于 cooldown |
| `timeout` | `20` | 探针超时，最多 20 秒，预留脚本总超时余量 |
| `strikes` | `2` | 实验候选票异常观察阈值 |
| `force_http` | `0` | `1` 主动中止匹配的 WebSocket 握手，等待客户端回退；需要设备实测 |

## 诊断、隐私与限制

本地保留最近 24 条结构化事件、最多约 64 组身份状态和 512 条轮次/请求记录。请求关联保留一天，轮次/身份记录闲置两天后清理。状态面板函数可供支持相应输入的运行环境调用；模块不声明自动面板或定时任务。

脚本只在本机保存 state、摘要标识、时间、长度、原因和计数，不保存认证头、提示词、回答或完整原始会话 ID，也不上传给第三方。state 本身仍属于敏感路由数据；请勿公开持久化存储内容。

本项目不能保证模型质量、账号额度或路由结果。MITM 和远程脚本具有读取流量的能力，请只使用信任的代码源。真实 Shadowrocket 横幅、压缩正文、请求 ID 稳定性及设备并发行为尚需实机验证；本地测试不代表实机验收。
